---
title: "Authentication"
description: "Sign in through the browser and manage credentials for one or more workspaces."
---

The CLI uses your browser to sign you in and securely saves your session, so you never need to enter an API key.

## Sign in

```bash
neetorecord login --subdomain your-workspace
```

Your browser opens to complete sign-in. The CLI also prints the sign-in URL in case the browser does not open, and waits up to five minutes for you to approve. Once you approve it, the CLI saves credentials for that subdomain. If you omit `--subdomain`, the CLI prompts for it.

<Tip>
  Your subdomain is the first part of your workspace URL - for
  `https://spinkart.neetorecord.com`, the subdomain is `spinkart`. See
  [Workspace subdomain](/cli/workspace-subdomain).
</Tip>

## Where credentials are stored

Credentials for every signed-in workspace live in a single file:

```text
~/.config/neetorecord/auth.json
```

Removing this file signs you out of every workspace, the same as `neetorecord logout --all`.

## Check who you are

```bash
neetorecord whoami
```

Lists every signed-in account. When exactly one is signed in, it is marked `(default)`. Pass `--subdomain <name>` to show just one.

## Sign out

```bash
neetorecord logout --subdomain your-workspace    # remove one workspace
neetorecord logout --all                         # remove every workspace
neetorecord logout                               # remove the only one, if a single workspace is signed in
```

## Working with multiple workspaces

You can sign in to several subdomains at once. To add another workspace, name its subdomain:

```bash
neetorecord login --subdomain globex
```

When more than one workspace is signed in, every command that talks to the API requires `--subdomain`. If you omit it, the CLI errors and lists the signed-in workspaces.

```bash
neetorecord recordings list --subdomain acme
neetorecord recordings list --subdomain globex
```

With one signed-in workspace, it is the default and `--subdomain` stays optional.

## Environment variables

`NEETORECORD_BASE_URL` overrides the server the CLI talks to. By default every command, including `login`, uses `https://<subdomain>.neetorecord.com`. Set the variable to point the CLI at a staging or local server. Every request, including the session token saved in `~/.config/neetorecord/auth.json`, goes to that server, so only point it at a server you trust:

```bash
export NEETORECORD_BASE_URL=https://acme.neetorecord.net
neetorecord login --subdomain acme
```

## Troubleshooting

If sign-in or connection problems come up, run `neetorecord doctor` first. See [Troubleshooting](/cli/troubleshooting) for common issues and fixes.
