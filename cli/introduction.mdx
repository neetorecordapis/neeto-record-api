The **NeetoRecord CLI** (`neetorecord`) lets you manage NeetoRecord from your terminal. It covers the [v2 REST API](/api/introduction): list and search recordings, generate transcripts and chapters, organize folders and tags, pull analytics, and automate bulk changes.

It is designed for people comfortable with a terminal or HTTP. You do not need to be a developer: run `neetorecord setup` to connect an AI assistant such as Claude or Cursor, then describe the task in plain language.

## CLI vs MCP: which should I use?

NeetoRecord's [MCP server](/mcp/introduction) reaches nearly everything the CLI does - recordings, transcripts, chapters, folders, tags, CTAs, analytics, and recording requests. Only the CLI manages [team members](/cli-reference/team-members), and only MCP reads a publicly shared recording in another workspace. Everywhere else the two overlap, so choose on how the work reaches NeetoRecord.

### Reach for the CLI when

- **No AI assistant should be in the loop.** A cron entry or a CI step runs `neetorecord` with nothing but the binary and the workspace you already signed in to - no assistant open, no model account, no tokens spent per run. Over MCP, something with model access has to be running before any call happens at all.
- **The output feeds another program.** `--quiet` prints the bare folder id for the next command; `--json` returns records plus pagination for `jq`, a spreadsheet, or your own script. An assistant replies in prose you would have to copy out by hand.
- **You are working through thousands of records.** Over MCP every page is a separate tool call, and a list that long crowds out the assistant's context. The CLI pages on your terms instead: `--page-size 100` with `--json` returns `total_pages` and `total_records` alongside the records, so a loop knows how many pages are left and walks all of them unattended. Each page lands in a file or goes straight into `jq`, so nothing has to be held in memory and the size of the list stops mattering.
- **You need the same run every time.** A `neetorecord` command is plain text you can save. Drop it into a runbook or a pull request and anyone can read exactly what it will do before it runs, then run it later and get the identical call. An assistant works from a prompt rather than a fixed command, so the same request can come out as a different set of calls on a different day.

### Reach for MCP instead when

- **The details live in your chat, not in your head.** An email, a thread, or a pasted note turns into a recording's summary, its tags, or a CTA with no retyping. The CLI cannot see any of it.
- **You have not decided the steps yet.** "Find the demo where the customer asked about pricing and share it" means looking at what is there and choosing. A command can only carry out a decision you have already made.
- **One request should cover several steps.** Generate the transcript, wait for it to finish, generate chapters from it, and write the summary onto the recording, with no glue between commands.
- **The answer is inside the recording.** The assistant searches the transcripts, names the recording, and looks at the frame at that timestamp, because the screenshot arrives as an image. The CLI returns a list and a screenshot URL, so the reading and the looking stay with you.
- **The person doing it does not use a terminal.** NeetoRecord hosts the server, so there is nothing to install or keep updated.

<Tip>
  You can have both. Run [`neetorecord setup claude`](/cli/ai-assistants) and your
  AI assistant drives the CLI itself, so a plain-language request still ends in
  an exact command you can read, repeat, and paste into a script.
</Tip>

## What you need

1. Access to one or more NeetoRecord workspaces.
2. Permission to manage the resources you want to work with (recordings, folders, team members, and so on).
3. The `neetorecord` binary. See [Installation](/cli/installation).

<Note>
  Unlike the API, which authenticates with an `X-Api-Key` header, the CLI signs
  you in through your browser and stores credentials locally. See
  [Authentication](/cli/authentication).
</Note>
